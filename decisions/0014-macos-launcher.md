# 0014. macOS launcher: a Python launcher that calls sandbox_init, and teardown by profile marker

Date: 2026-10-09
Status: accepted

## Context

Milestone 1 needs a launcher that confines the workload with Seatbelt before any workload code runs, inheritable by every child, with only the per-run proxy reachable, and a way to stop every process the workload starts. PLAN.md's open-questions table asked for an evaluation of `sandbox-exec -f` with the generated profile against a small helper calling `sandbox_init`, choosing what passes the inheritance, grant, egress, and cleanup tests with the least custom native code. No Mac was available; every observation below comes from the GitHub-hosted `macos-15` runner: macOS 15.7.9 (build 24G830), kernel Darwin 24.6.0, Apple M1 (Virtual), runner image `macos15` 20260907.0337.1, System Integrity Protection disabled (as on every hosted runner).

Three exploration runs on a temporary branch tried both launchers and probed the kernel before the backend was written: [37990583614](https://github.com/johnnygreco/agent-in-a-box/actions/runs/37990583614), [37991133668](https://github.com/johnnygreco/agent-in-a-box/actions/runs/37991133668), and [37992019634](https://github.com/johnnygreco/agent-in-a-box/actions/runs/37992019634). The branch and its workflow are deleted; what they showed is recorded here and is re-checked on every push by `tests/native/macos/` in the `macos-native` CI job.

## Decision

**The launcher is a Python program that calls `sandbox_init` through ctypes; no compiled helper, and `sandbox-exec` is not used.** `native/macos/` stays empty.

1. **Launch.** The supervisor starts `python -m agent_in_a_box.supervisor.backends.seatbelt.launcher` (the source route's launcher slot) as an ordinary process, with the launch file (the SBPL profile and its self-probes) on one descriptor and a report pipe on another. The launcher calls `sandbox_init(profile, 0, &error)` from libSystem (`seatbelt/sandbox.py`, the only native shim), runs its self-probes, reports the probe results and the SHA-256 of the profile it applied, closes every other descriptor, and replaces itself with the workload, which waits for the supervisor's admit.
2. **Self-probes inside**: listing an ungranted directory, creating a file in world-writable `/private/tmp`, TCP to another IPv4 and IPv6 loopback port, TCP to a public address, UDP to the proxy's own port, a Unix socket, a kernel-control socket, and a `stat` of each protected path. Each must fail with EPERM; a protected path that does not exist on the host must be absent.
3. **Checks from outside** (`confirm`): `sandbox_check(pid, NULL, 0)` reports the workload confined; the workload carries this run's marker (below); the kernel refuses the workload read and write on each protected path that exists; the applied profile's hash equals the prepared one. Only then is the workload admitted.
4. **Teardown by marker** (`seatbelt/accounting.py`). Seatbelt has no process namespace. Each run's profile allows a Mach lookup of one run-specific name that no service uses (the marker) and, like every deny-default profile, refuses a second run-specific name (the control). `sandbox_check(pid, "mach-lookup", global-name, …)` answers without performing the lookup. Marker allowed and control refused identifies exactly this run's processes: an unconfined process and an allow-default sandbox allow both; another deny-default sandbox refuses both; an exited process gets a refusal for everything. `stop` lists every process (`/bin/ps`), freezes each member with SIGSTOP until no new member appears, checks each frozen process again, kills the members with SIGKILL, resumes any process whose PID was reused in the meantime, and verifies that no member remains. On the runner, 463 processes were checked in 0.06 s, and a detached `setsid` grandchild was found.
5. **The network rule is `(allow network-outbound (remote tcp "localhost:PORT"))`.** The kernel accepts only `*` or `localhost` as the host ("host must be * or localhost in network address" for `127.0.0.1`), and `localhost` means 127.0.0.1 and ::1, not 127.0.0.2. The proxy listens only on 127.0.0.1, so the backend holds `[::1]:PORT` for the run, bound and not listening: no other service can be listening there, and a connection to it reaches nothing (on the runner it goes unanswered and times out). If another process already holds it, the launch is refused.
6. **Process information is refused explicitly.** `(deny default)` does not cover `process-info*` on macOS 15: under it, a workload read the arguments and environment of its parent with `sysctl kern.procargs2`, listed every process, and resolved other processes' executables. The profile therefore ends its baseline with `(deny process-info*)` followed by `(allow process-info* (target self))`. `(deny process-info*)` alone makes bash abort, and neither `(deny process-info* (target others))` nor denying the `kern.procargs2` sysctl name refused the read.
7. **The baseline was confirmed on the runner**, one entry at a time (decisions/0008): the profile was rendered without each entry and the workload's programs were run under it. Kept, each with its evidence in `os_baseline.py` and re-checked by `tests/native/macos/test_seatbelt_baseline.py`: `process-fork`; signals within the sandbox; `sysctl-read` narrowed to named parameters and the `hw.` prefix (previously unfiltered); `file-read-data` on `/` (without it the dynamic loader aborts every program before `main`); the local time zone files and the `/etc` and `/var` links they resolve through; locale data for `LANG=C.UTF-8`; `SystemVersion.plist`; `openssl.cnf` (curl refuses to start without it); the `/bin/sh` selector link; `/dev/null`; the `/dev/fd` listing (without it, Python closes every possible descriptor before each child: 20 children took 6.8 s instead of 0.08 s at the runner's limit of 1,048,576 descriptors); and the directory-service lookup. Removed because nothing failed and no program read them: `/usr/lib`, `/System/Library` (except `SystemVersion.plist`), the OS cryptex, `/usr/share/zoneinfo`, ICU data, `/dev/urandom`, and the `/tmp` link metadata. (A first draft also removed the `/var` link's metadata; the native suite showed the time zone link then fails to resolve, and it was restored with that evidence.) System code comes from the dyld shared cache, which needs no rule; `file-map-executable` was not needed for Python's extension modules.

8. **The working directory can be listed.** `getcwd(3)` on macOS opens the working directory, which needs `file-read-data` on it, and Python asks for it at its first import when started with `-c`. With only the plan's metadata grant on the workspace, every child Python failed with a bare `PermissionError` in the first `macos-native` run. The Seatbelt backend therefore adds `(allow file-read-data (literal <working directory>))` to each run's profile, rendered from the run, not from the grant plan: the workload can list the names in its working directory, and reading what they name still needs a grant. The grant plan and the Linux backend, where `getcwd` is a system call that needs no access, are unchanged. A Python started in another directory the workload cannot read still fails this way; it is disclosed.

## What the runner showed about the two launchers

- **Enforcement is identical.** The same profile applied through `sandbox-exec -f` and through `sandbox_init` produced the same exit status and output for every command tried (the harness import, a standard-library tour, bash, sh, curl through the proxy, `nohup`, a child Python, and a refused canary read).
- **Errors.** A profile the kernel rejects comes back from `sandbox_init` as text in the error buffer ("unbound variable: nonsense-op at <input string>, line 1, column 19"); `sandbox-exec` prints the same text to stderr and exits 65.
- **A second `sandbox_init`** inside a confined process fails ("sandbox initialization failed: Operation not permitted"), and the first profile still applies: the workload cannot widen its profile.
- **Descriptors** opened before `sandbox_init` stay usable, so the workload's stdout and stderr files in the run's private directory work without a grant.

## Alternatives rejected

- **`sandbox-exec -f profile.sb`.** Equal enforcement and no native code, and it confines Python's own startup as well. But a rejected profile surfaces only as text on the workload's stderr, the self-probes would still need a Python program after it, and the hash of what was applied cannot be reported by the program that applied it. Both interfaces are marked deprecated by Apple; `sandbox_init` is declared in `<sandbox.h>`, and `sandbox-exec` adds a command-line wrapper over the same call.
- **A compiled helper calling `sandbox_init`.** It is native code with a build step for one call that ctypes makes directly.
- **Teardown by process group or session.** A detached process leaves both; the profile is the one thing it cannot leave.
- **A path as the marker.** `sandbox_check` with a path filter answered "refused" for a path that does not exist even for an unconfined process, so a path marker could not tell processes apart. Outside checks on paths are therefore made only for paths that exist.

## Consequences

- No native code to build. The launcher's Python startup and imports run before confinement; they are the supervisor's own interpreter and package, and no workload code runs until the launcher has confined itself and the supervisor has admitted the workload.
- Known limits, disclosed through `BackendCapabilities.notes` and reference/platform-differences.md: the names of top-level directories are visible (the loader lists `/`); inside a protected directory a missing name reports ENOENT and an existing one EPERM, so names can be probed but not read; programs try to read their own executable and are refused, harmlessly; macOS's `/bin/bash` 3.2 writes here-documents to `/var/tmp`, `/tmp`, or the working directory, ignoring `TMPDIR`, so a here-document fails unless the working directory is writable.
- The PID-reuse window in teardown is closed by checking each frozen process again before killing it; a process that the workload's last member forks after the final listing is impossible because every member is frozen first.
- macOS impact: this is the macOS backend. Shared code changed in the same work: runtime tool grants now resolve programs on the workload's own `PATH` (`runs.workload_path`) rather than the supervisor's, so the grant names the program the workload runs. No contract record, conformance expectation, or evidence schema changes.
