# 0009. Oracle cases: the official Cedar CLI for authorization semantics, hand-authored rules for our compiler

Date: 2026-10-09
Status: accepted

## Context

Invariant 6 says expected outcomes for oracle cases are never generated by the implementation under test. Milestone 0 first met this with 37 hand-extracted cases. On 2026-10-09 the owner ruled that cases derived from third-party material stay outside the public tree, in the git-ignored working folder, and that the public oracle must come from an independent implementation or from this plan's stated rules (PLAN.md, Open questions and defaults: Oracle contract cases).

## Decision

Two public sources of expected outcomes, each matched to what it can independently judge:

1. **Authorization semantics: the official Cedar CLI.** `tooling/generate_oracle_cases.py` uses only the standard library and the pinned `cedar-policy-cli` (4.12.0, checksum verified against `.toolchain/installed.json`), and never imports our package; a test checks that by reading its imports. For every shipped policy variant, plus P0 with a policy that overflows at evaluation time, it sends 18 requests to the CLI: five methods by three paths for HttpRequest, and three endpoints for NetworkConnect. It records the CLI's decision, determining policies, and erroring policies in `tests/oracle/cedar_cli_cases.json`, one case per line, with the CLI version, binary checksum, schema hash, and each policy set's hash. The request in each case is written in Cedar's own terms, independently of our request construction.
   `tests/oracle/test_cedar_cli_oracle.py` checks both of our evaluators against every case: the raw decision, the determining policies, and the erroring policies must match. The enforced decision must follow our wrapper rule: allow only when Cedar allows and reports no error. A further test checks that our request construction builds the same request the oracle describes. A case whose policy text changed fails as stale until the file is regenerated and its diff reviewed.
2. **Our compiler's subset rules: hand-authored from PLAN.md.** No independent implementation of our filesystem subset exists, so its accepted shapes, rejected shapes, and derived routes are authored by hand in `tests/policy/test_compiler.py`, each with the PLAN.md rule it follows.

The hand-authored evaluator contract cases (`tests/policy/test_evaluator_contract.py`) stay, and are also cross-checked live against the CLI. Local working cases, if present in the ignored folder, run through `tests/local_cases/` and are skipped otherwise.

## Alternatives rejected

- **Keeping the 37 extracted cases in the tree.** This is ruled out by the owner.
- **Generating expectations with the bridge or cedarpy.** Both are implementations under test.
- **Asking the CLI at test time only.** The tests already do this for the contract cases, but a committed oracle file makes each expectation reviewable in a diff, and lets the tests run when the CLI is not installed (only the bridge comparison needs the toolchain).

## Consequences

- The oracle's independence is about implementation, not about source code: the CLI, cedarpy, and the bridge are all built from the same cedar-policy 4.12.0 crate. The cases check that our adapters (id mapping, error handling, request shapes, the wrapper rule) preserve Cedar's answers; they do not check Cedar against itself.
- Moving to a new Cedar version means regenerating the file with the new pinned CLI, in the same change as the version ADR.
- The STATUS.md gate item "Oracle contract cases in the public tree" is met by `tests/oracle/` plus the hand-authored compiler cases.
